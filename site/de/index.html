So funktioniert's

Ein Orchestrator. So viele Worker, wie du willst.

Gib dem Orchestrator ein Ziel. Er teilt die Arbeit auf und schickt Jobs an die anderen Agents. Du siehst alles live auf dem Board und greifst nur ein, wenn dich jemand braucht.

  1. 1
    Team starten

    Wähl einen Ordner und eine Vorlage wie Dev HQ: ein Orchestrator plus Frontend-, Backend- und Reviewer-Agents, jeder im eigenen Terminal.

  2. 2
    Jobs fliegen übers Board

    Der Orchestrator gibt jedem Worker einen Job. Jeder Job ist eine Live-Linie vom Absender zum Worker, beschriftet mit seinem Inhalt.

  3. 3
    Worker melden sich zurück

    Ist ein Worker fertig, wird sein Bericht ins Terminal des Orchestrators getippt, und der plant den nächsten Schritt.

Funktionen

Alles, was du für eine ganze Flotte von Agents brauchst

Für alle, die fünf, zehn oder zwanzig Agent-Sessions gleichzeitig laufen lassen, über Anbieter hinweg, und genug vom Jonglieren mit Terminal-Fenstern haben.

  • Jeder Agent in einem echten Terminal

    Claude Code, Codex, Gemini CLI, Grok Build, OpenCode oder ein beliebiger Befehl, jeweils die echte CLI im eigenen Terminal. Slash-Commands, Prompts und TUIs funktionieren wie gewohnt. Misch sie in einem Team.

  • Orchestratoren, die delegieren

    Ein Orchestrator schickt Jobs an Worker-Agents. Jeder Job erscheint als animierte Linie, und der Bericht des Workers geht direkt zurück.

  • Dein Handy als Fernbedienung Neu

    QR-Code scannen und jeden Agent vom Handy aus verfolgen: Terminal mitlesen, „Needs you“-Rückfragen beantworten, Nachrichten schicken oder ein Team auf deinem Rechner starten.

  • Übergabe in beide Richtungen Neu

    Schieb eine Session mit einem Tipp vom Rechner aufs Handy und zurück. Der Agent läuft die ganze Zeit auf deinem Rechner weiter; nichts startet neu.

  • Teilbare Team-Rezepte Neu

    Teil ein Team (Rollen, Agents, Modelle, erste Prompts) als Link oder als „Run in GridHive“-Badge für dein README. Wer es in seiner App öffnet, sieht zuerst jeden Prompt.

  • Loops & Übergaben

    Schick einen Prompt nach Zeitplan oder bei Leerlauf erneut, und brief einen Agent mit der Arbeit eines anderen, sogar anbieterübergreifend, wenn einer sein Limit erreicht.

  • Vorlagen & Projekt-Frames

    Starte Dev HQ (13 Agents), Bug squad, Docs crew und mehr mit einem Klick. Teams sitzen in beschrifteten Frames auf dem Board.

  • Actions-Inbox

    Beantworte Berechtigungsabfragen und Rückfragen in einer einzigen Liste. Schluss mit der Suche nach dem Terminal, das seit zehn Minuten wartet.

  • Alarm bei hängenden Agents

    Erkennt Agents, die hängen oder viel zu lange laufen, und lässt dich sie direkt aus der Inbox anstupsen, unterbrechen oder ignorieren.

  • Fortschritt & Mission Map

    Todo-Fortschritt pro Team, dazu eine Karte aus Orchestrator, Teams und Agents, filterbar nach Working, Needs you, Idle oder Done.

  • Verbrauch & Budgets

    Token-Verbrauch pro Board, Account und Modell, direkt aus den lokalen Logs von Claude Code. Setz Budgets pro Tag, pro 5 Stunden oder pro Woche.

  • Mehrere Accounts pro Agent

    Melde dich mit mehreren Claude-, Codex- oder Gemini-Accounts an. Erreicht einer sein Plan-Limit, wechselt der Agent zum nächsten Account oder zu einem anderen Anbieter und macht genau dort weiter.

  • Ein Worktree pro Agent

    Gib jedem Agent auf Wunsch einen eigenen git-Worktree und Branch, dann prüf den Diff, committe und merge in einem Panel.

  • Live-Browser-Tiles

    Browser-Tiles auf dem Board, die Agents mit sichtbarem Cursor steuern können. Starte einen Dev-Server, und GridHive bietet dir gleich eine Vorschau-Tile an.

  • Recaps & Handy-Pings

    Ein täglicher Recap an Slack oder Discord. „Needs you“-Alarme an Slack, Discord oder per kostenloser ntfy-App auf den Sperrbildschirm deines Handys.

  • Eine echte App für Windows & Mac

    Icon im Tray oder in der Menüleiste, Badge in Taskleiste oder Dock und native Benachrichtigungen. Lös Konsolen auf einen zweiten Monitor aus und wähl aus vier Themes.

Kostenlos & lokal

Dein Rechner. Dein Login. Dein Code.

GridHive ist eine lokale App, kein Cloud-Dienst. Kein Account nötig, nichts zu bezahlen.

  • Keine API-Keys. Agents laufen über den Abo-Login der jeweiligen CLI. GridHive blendet ANTHROPIC_API_KEY in seinen Terminals sogar aus, damit du nicht aus Versehen pro Token zahlst.
  • Nichts in der Cloud. Das Board ist ein lokaler Server auf 127.0.0.1 mit einem Token pro Start. Der Handy-Zugriff ist aus, bis du ihn einschaltest, und nur gekoppelte Handys kommen rein. Dein Code geht nur dorthin, wohin die Agents selbst ihn schicken.
  • Deine Einstellungen bleiben deine. Hooks werden pro Agent über eine temporäre Settings-Datei übergeben. In ~/.claude ändert sich nichts.
  • MIT und Open Source. Lies jede Zeile, meld Issues, schick Pull Requests, fork es.

Loslegen

In zwei Minuten startklar

Voraussetzungen

  • Windows 10 oder 11 (x64) oder macOS 12 oder neuer (Apple Silicon oder Intel) für die Desktop-App
  • Claude Code installiert und angemeldet. Führ vorher einmal claude in einem Terminal aus.
  • Linux oder ohne Installer: npx gridhive (braucht Node 20+)
  1. 1

    App herunterladen

    Windows: GridHive-Setup-0.0.7.exe. Mac: das Disk-Image für deinen Chip. Nicht sicher? Apple-Menü → About This Mac (Über diesen Mac): „Apple M1/M2/M3/M4…“ ist Apple Silicon, „Intel“ ist Intel.

    Windows Mac · Apple Silicon Mac · Intel
  2. 2

    Installieren und beim ersten Start erlauben

    Windows: Die Installation gilt nur für deinen Benutzer, Adminrechte brauchst du nicht. Die App ist noch nicht code-signiert, deshalb zeigt Windows eventuell „Der Computer wurde durch Windows geschützt“. Klick auf More info (Weitere Informationen) und dann auf Run anyway (Trotzdem ausführen).

    Mac: Öffne das Disk-Image und zieh GridHive in Programme. Die App ist noch nicht von Apple signiert, deshalb wird der erste Start blockiert: Öffne System Settings → Privacy & Security (Systemeinstellungen → Datenschutz & Sicherheit), scroll nach unten, klick auf Open Anyway (Dennoch öffnen) und bestätige. Das musst du nur einmal machen. Neue Versionen kündigt das Menü in der Menüleiste an.

  3. 3

    Team starten

    Öffne GridHive, klick auf Templates, wähl einen Ordner und starte Dev HQ, oder füg mit New agent einen einzelnen Agent hinzu.

Oder mit npx starten (Windows, macOS, Linux)

$ npx gridhive   # startet das Board und öffnet es in deinem Browser

Braucht Node 20 oder neuer. Mit --port 5000 nimmst du einen anderen Port, oder du installierst es einmal mit npm i -g gridhive und startest gridhive.

Aus dem Quellcode starten (Windows, macOS, Linux)

$ git clone https://github.com/customerimpact/gridhive
$ cd gridhive
$ npm install && npm run build
$ npm start   # öffnet das Board in deinem Browser

FAQ

Fragen und Antworten

Ist das wirklich kostenlos?

Ja. GridHive ist Open Source unter MIT-Lizenz. Kein Abo, keine Lizenzprüfung, und einen Account brauchst du auch nicht. Du brauchst nur die Pläne der Agents, die du nutzt.

Welche Agents werden unterstützt?

Claude Code, OpenAI Codex CLI, Gemini CLI, Grok Build und OpenCode, dazu jeder Befehl, den du willst. Installation und Login erledigst du für jeden unter Settings → Agents & accounts. Agents mit Claude Code und Codex können außerdem über die Orchestrator-Tools Jobs verteilen.

Kann ich es vom Handy aus nutzen?

Ja, im selben WLAN: Schalte Settings → Integrations → Phone ein und scanne den QR-Code. Dein Handy zeigt jeden Agent mit Terminal und Rückfragen und kann neue starten; die Agents laufen weiter auf deinem Rechner. Handy-Zugriff von überall, mit kostenlosem Account, kommt bald: Trag dich unten für den Early Access ein.

Was ist ein Rezept?

Ein Team-Setup als Link: Rollen, Agents, Modelle und erste Prompts. Teil es mit deinem Team oder pack ein „Run in GridHive“-Badge in dein README. Ein geöffnetes Rezept wird als Vorlage gespeichert und zeigt dir zuerst jeden Prompt; nichts startet, bevor du auf Launch klickst. Deine Accounts und Ordner stehen nie im Link.

Verbraucht es meine API-Credits?

Nein. Agents nutzen jede CLI mit deinem eigenen Abo-Login, genau wie in einem normalen Terminal. GridHive blendet ANTHROPIC_API_KEY und ANTHROPIC_AUTH_TOKEN in seinen Terminals aus, damit Claude Code nicht plötzlich auf Abrechnung pro Token umschaltet.

Genehmigt es Berechtigungen automatisch?

Nein. Jeder Agent behält seine eigenen Berechtigungsabfragen. GridHive sagt dir, wenn eine wartet, und du beantwortest sie in der Actions-Inbox.

Gibt es eine Mac-Version?

Ja. Lade oben das Disk-Image für Apple Silicon (M1 und neuer) oder Intel-Macs herunter; es braucht macOS 12 oder neuer. Die App ist noch nicht von Apple signiert, also erlaub sie einmal unter System Settings → Privacy & Security → Open Anyway. Unter Linux startest du GridHive aus dem Quellcode und nutzt es im Browser.

Wo werden meine Daten gespeichert?

Auf deinem Rechner. Board-Layout und Einstellungen liegen in ~/.gridhive in deinem Home-Ordner. Unterhaltungen bleiben in den Ordnern von Claude Code. Die Desktop-App macht genau einen eigenen Netzwerkaufruf: Sie prüft GitHub Releases auf Updates.

Warum meldet Windows „Der Computer wurde durch Windows geschützt“?

Der Installer ist noch nicht code-signiert, deshalb kennt SmartScreen ihn nicht. Klick auf More info (Weitere Informationen) und dann auf Run anyway (Trotzdem ausführen). Der komplette Quellcode und der Build-Workflow liegen auf GitHub, falls du lieber selbst prüfen oder bauen willst.

Gehört GridHive zu Anthropic?

Nein. GridHive ist ein unabhängiges Open-Source-Projekt, weder mit Anthropic verbunden noch von Anthropic unterstützt. „Claude“ und „Claude Code“ sind Marken von Anthropic.
